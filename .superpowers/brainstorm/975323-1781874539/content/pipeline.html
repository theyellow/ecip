Section 4 of 5 — Three triggers → one shared ingestion path

— Three Entry Points —
⏱ Trigger 1 — Scheduled
A master @Scheduled job runs every minute, queries enrichment_sources for sources whose cron expression is due, then fans out one fetch per source.
@Scheduled(cron = "17 * * * * *") // runs at :17 every minute // checks each source's own cron // via CronExpression.isMatch()
⬡ Trigger 2 — Topic-driven (Kafka)
Listens on knowledge.entity.created. When a new entity lands in the graph, relevant connectors are queried with the entity name/concept as search term.
@KafkaListener topic = "knowledge.entity.created" // Connector selection: all // enabled sources for that tenant // where mode = SEARCH capable
▶ Trigger 3 — Manual REST
Admin POSTs to trigger an immediate one-shot run. Returns a runId immediately; client polls for status. Useful for testing new API keys.
POST /api/v1/admin/enrichment /sources/{id}/trigger → 202 Accepted → { "runId": "uuid" } GET /sources/{id}/runs/{runId}

— Implementation Notes —
Dynamic cron scheduling
// One fixed @Scheduled fires at :17 each minute // It queries enrichment_sources and uses // Spring's CronExpression to check if due: var expr = CronExpression.parse(source.scheduleCron()); var next = expr.next(ZonedDateTime.now().minusMinutes(1)); if (next != null && !next.isAfter(ZonedDateTime.now())) { runConnector(source); // it's due } // Cron strings stored per source, e.g.: // "0 17 3 * * *" (03:17 daily) // "0 41 2 * * MON" (02:41 Mondays)
Error handling & partial success
// Per-item errors don't abort the stream: connector.fetch(req, ctx) .onErrorContinue((err, item) -> { log.warn("skip item: {}", err.getMessage()); runRecord.incrementErrors(); }) .flatMap(result -> ingest(result)) ... // Run status: // SUCCESS — all items ingested cleanly // PARTIAL — some items failed (errors > 0) // FAILURE — connector itself threw (auth, net)
Cron offset rule — per CLAUDE.md: cron expressions must never land on exact round times. Each source gets a seeded random offset: e.g. EnrichmentSourceService generates the offset on first save and stores it in schedule_cron — never 0 0 3 * * *, always 0 17 3 * * *.
