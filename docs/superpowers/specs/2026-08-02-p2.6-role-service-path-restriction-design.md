# P2.6 — ROLE_SERVICE Path Restriction + RBAC Modeling (RT2-014 / RT-020)

> Status: **design approved**, ready for implementation plan
> Date: 2026-08-02
> Backlog: RT2-014 / RT-020 (§0a, P2.6, size M)
> Finding: `RED_TEAM_REPORT_2026-07-18.md` RT2-014 (API5 Broken Function Level Authorization)
> Module: `emcip-admin-api` (WebFlux + R2DBC, reactive)

---

## 1. Problem statement & threat model

`ServiceTokenAuthenticationFilter` authenticates the `X-Service-Token` header and grants
`ROLE_SERVICE` **with no path restriction**. A holder of the shared service token thus satisfies
`SecurityConfig`'s `.anyExchange().authenticated()` on **every** endpoint. The only thing between a
leaked token and any user endpoint is that each of the 19 controllers remembered its method-level
`@PreAuthorize` — a fragile, single-layer defense with no path/role backstop. `ROLE_SERVICE` is also
absent from `RolePermissions` (the RBAC matrix), so it is an invisible authority.

**Verified against current code:**

- admin-api **only *sends*** the service token outbound (`WebClientConfig` + `*Client` classes →
  policy-engine, intent-classifier, audit-service, moderation-service, tdlib-adapter). **Nothing sends
  `X-Service-Token` *to* admin-api**, and admin-api exposes **no `/api/internal/**` endpoints**.
- The fleet pattern (moderation-service / audit-service `ServiceTokenFilter`): the token gates
  `/api/**` only — `if (!path.startsWith("/api/")) return chain.filter(exchange);` — leaving
  `/actuator/**` open, which is how Prometheus scrapes them tokenless.
- admin-api is the outlier: it permits **only** `/actuator/health`, so Prometheus scraping
  `emcip-admin-api:9087/actuator/prometheus` (per `helm/.../prometheus-configmap.yaml`, no auth header)
  currently 401s — admin-api metrics are effectively uncollected.
- `Role` (ADMIN/TENANT_ADMIN/MODERATOR/ANALYST/VIEWER) is **user-assignable** (JWT `role` claim,
  `UserManagementService`), so `ROLE_SERVICE` must NOT be added to it.

## 2. Design decisions (approved)

| # | Decision | Choice | Rationale |
|---|----------|--------|-----------|
| D1 | Approach | **Restrict + model in RBAC** (keep the filter) | Keeps a (now-scoped) inbound surface for a future internal callback and models the identity, per the finding. (Removing the filter outright was the alternative.) |
| D2 | Scope | **Fleet-consistent**: `ROLE_SERVICE` granted only for `/api/internal/**`; `/actuator/**` open | Matches the other services' token filters (token gates `/api/**`, actuator open). `/api/internal/**` is reserved — no such endpoints exist yet. |
| D3 | Valid token on a non-internal `/api/**` path | **403 Forbidden** (+ `log.warn`) | Explicit, auditable denial; the actual BFLA fix — the token can no longer authorize user endpoints. |
| D4 | Modeling `ROLE_SERVICE` | Explicit **empty-permission** service identity in `RolePermissions`, **not** in the `Role` enum | The `Role` enum is user-assignable; `ROLE_SERVICE` holds zero user Permissions so it can never satisfy a user-permission `@PreAuthorize`. |
| D5 | Actuator scrape | **Fold in**: permit `/actuator/prometheus`, `/actuator/info`, `/actuator/metrics(/**)` | Aligns admin-api with the fleet and fixes its currently-broken metrics scrape; we are already editing the actuator authz rules. No Helm change. |

## 3. Filter design — `ServiceTokenAuthenticationFilter`

Mirror the fleet filter's shape (`!path.startsWith("/api/")` → passthrough), then scope the granted
authority to the internal prefix:

```
path = request path
if (!path.startsWith("/api/"))        return chain.filter(exchange);   // actuator etc. — token irrelevant
token = header "X-Service-Token"
if (token == null)                    return chain.filter(exchange);   // JWT filter handles user /api/ auth
if (!constantTimeEquals(configured, token)) { 401; return; }           // invalid token on an /api/ path
// valid token on an /api/ path:
if (path.startsWith("/api/internal/")) {
    auth = UsernamePasswordAuthenticationToken("service", null, [ROLE_SERVICE]);
    return chain.filter(exchange).contextWrite(withAuthentication(auth));
}
// valid token, but NOT an internal path → BFLA fix
log.warn("Service token presented on non-internal path {} from {}", path, remoteAddress);
403 Forbidden; return;
```

- The internal prefix is a single shared constant (`INTERNAL_PATH_PREFIX = "/api/internal/"`), reused
  by the filter (`startsWith`) and `SecurityConfig` (`pathMatchers("/api/internal/**")`).
- `@PostConstruct validateToken()` (reject the default token) is unchanged.
- Behavior change summary: a valid token now grants `ROLE_SERVICE` **only** on `/api/internal/**`;
  on any other `/api/**` path it returns **403**; on `/actuator/**` (and other non-`/api/` paths) the
  token is ignored and the request passes through.

## 4. `SecurityConfig` authorizeExchange

Current (lines 67–77): permit auth endpoints + `/actuator/health(/**)`, else `.authenticated()`.
New (order: most specific first):

```
auth.pathMatchers(POST, "/api/auth/token", "/auth/token", "/api/auth/refresh", "/api/auth/logout").permitAll()
    .pathMatchers("/actuator/health", "/actuator/health/**").permitAll()
    .pathMatchers("/actuator/prometheus", "/actuator/info", "/actuator/metrics", "/actuator/metrics/**").permitAll()  // D5
    .pathMatchers("/api/internal/**").hasRole("SERVICE")   // D2 defense-in-depth (Spring maps ROLE_SERVICE → hasRole("SERVICE"))
    .anyExchange().authenticated()
```

No other `SecurityConfig` change (filter registration, CORS, CSP, headers untouched).

## 5. `RolePermissions` — model the service identity

Add, without touching the `Role` enum or `permissionsFor(...)`:

```java
/**
 * ROLE_SERVICE is a service identity granted by ServiceTokenAuthenticationFilter for internal
 * service-to-service calls, path-scoped to /api/internal/**. It holds NO user Permissions, so it can
 * never satisfy a user-permission @PreAuthorize on a user-facing endpoint. Modeled here so the RBAC
 * matrix is complete; it is deliberately NOT a member of the user-assignable Role enum.
 */
public static final Set<Permission> SERVICE_PERMISSIONS = EnumSet.noneOf(Permission.class);
```

## 6. Testing

### 6.1 `ServiceTokenAuthenticationFilterTest` (new)
Use `MockServerWebExchange` + a capturing `WebFilterChain`; set the token field via `ReflectionTestUtils`
(the `@Value` field, non-default to pass `validateToken`). Assert:
- valid token + `/api/internal/ping` → chain invoked; security context authority contains `ROLE_SERVICE`.
- valid token + `/api/users` → **403**, chain NOT invoked, no auth set.
- valid token + `/actuator/prometheus` → chain invoked, token ignored (no `ROLE_SERVICE`).
- invalid token + `/api/anything` → **401**, chain NOT invoked.
- no token + `/api/users` → chain invoked, no auth set (JWT filter will handle it downstream).

### 6.2 `SecurityFilterChainTest` (update, ~line 167)
The existing assertion that a service token yields `ROLE_SERVICE` must be re-scoped: assert
`ROLE_SERVICE` is granted for an `/api/internal/**` request and that a service token on a user endpoint
(e.g. `/api/users`) is denied (403). Add an assertion that an actuator metrics endpoint
(`/actuator/prometheus`) is reachable without a JWT.

Runner: Spring WebFlux test support (reactive); no Testcontainers.

## 8. Out of scope (deliberately)

- **Removing the inbound filter entirely** (the stronger alternative to D1) — not chosen; the filter is
  kept and scoped.
- **Per-service tokens / mTLS** for service-to-service auth (the shared static token is a broader design
  topic) — future/secrets-management ADR (P6), not this change.
- **Helm/Prometheus changes** — none needed (actuator is permitted, not token-gated).

## 9. Acceptance criteria

1. A valid service token grants `ROLE_SERVICE` **only** on `/api/internal/**`; on any other `/api/**`
   path it yields **403**; on `/actuator/**` it is ignored.
2. `ROLE_SERVICE` holds zero user Permissions and is modeled in `RolePermissions` (not in `Role`).
3. admin-api's actuator metrics endpoints (`/actuator/prometheus`/`info`/`metrics`) are reachable
   without a JWT (scrape fixed).
4. Filter + filter-chain tests cover grant / 403 / 401 / passthrough; `mvn -pl emcip-admin-api test` green.
5. BACKLOG/ROADMAP updated; spec committed.
