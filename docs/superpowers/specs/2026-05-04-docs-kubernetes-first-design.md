# Documentation Restructure: Kubernetes-First Design

**Date:** 2026-05-04
**Status:** Approved
**Scope:** Restructure all AsciiDoc guides so Kubernetes/microk8s is the primary operator path, Docker Compose is developer/patch tooling, CI/CD and operator responsibilities are clearly distinguished, and all documents use a clean print-safe color scheme.

---

## Context

EMCIP now has a working Helm chart (PR #13), mixed-cluster nodeSelector support (PR #14), and GitHub Actions image publishing (PR #14/15). The documentation still treats Docker Compose as the primary runtime and Kubernetes as a bolt-on appendix. This needs to be inverted.

There are two audiences:
- **Developer / CI** — builds images, runs tests, maintains code. Uses Docker Compose for local development.
- **Operator** — deploys and operates EMCIP in production on microk8s. Uses Helm.

The documents are viewed as rendered HTML (IDE/browser preview) and as PDFs generated by `mvn generate-sources` (asciidoctor-maven-plugin). The current `emcip-theme.yml` uses dark code backgrounds and gold accents which print poorly and have low contrast on screen.

### `documentation/emcip-screen.css` (HTML — new file)

New CSS file referenced by AsciiDoc documents for HTML rendering. Targets AsciiDoc's default HTML5 output structure. Key rules:
- `body`: `font-family: Georgia, serif; color: #1e293b; background: #ffffff; max-width: 960px; margin: 0 auto; padding: 2rem;`
- `h1, h2, h3, h4`: `color: #1e3a5f; font-family: Georgia, serif;`
- `h2`: `border-bottom: 2px solid #e2e8f0; padding-bottom: 0.3em;`
- `a`: `color: #2563eb;`
- `pre, code`: `background: #f1f5f9; color: #1e293b; border-left: 3px solid #3b82f6;`
- `pre`: `padding: 1rem; overflow-x: auto; border-radius: 4px;`
- `code` (inline): `padding: 0.1em 0.3em; border-radius: 3px;`
- `table`: standard bordered, `thead { background: #e2e8f0; color: #1e293b; }`
- `.admonitionblock`: `border-left: 3px solid #3b82f6; background: #f8fafc; padding: 0.75rem 1rem;`

### `pom.xml` — add HTML output execution

Add a second execution to the `asciidoctor-maven-plugin` config to produce HTML alongside PDF. The HTML execution must pass `emcip-screen.css` as a global asciidoctor attribute (e.g. `<stylesheet>emcip-screen.css</stylesheet>` or via `<attributes><stylesheet>emcip-screen.css</stylesheet></attributes>`). Do **not** add `:stylesheet:` to individual `.adoc` document headers — stylesheet wiring is done exclusively through the pom.xml plugin configuration so it applies uniformly to all documents without touching source files.

### Key content changes:

**New `== Deployment Paths` section:**
A short orientation table:

| | Kubernetes (microk8s) | Docker Compose |
|---|---|---|
| Purpose | Production, staging | Local dev, quick patch |
| Images | `ghcr.io/theyellow/ecip` (CI-built) | Local `docker build` |
| Config | `helm/emcip/values.yaml` | `.env` + `docker-compose.yml` |
| Start command | `helm upgrade --install ...` | `docker compose up` |

**New `=== CI/CD Responsibilities vs Operator Responsibilities`:**

Clear admonition-style table distinguishing what GitHub Actions does automatically vs what the operator must do manually. Examples:
- CI/CD: builds images, pushes to `ghcr.io`, runs tests
- Operator: creates Kubernetes secrets, runs `helm upgrade`, manages Telegram auth, monitors pods, restores backups

**New `=== Image Overview` under Kubernetes:**
Table of all 9 services showing exact `ghcr.io/theyellow/ecip/<service>:<tag>` image names and which tag variant is used on which cluster type (`:latest`, `:jvm-latest`, `:native-amd64`).

**Kubernetes diagram:**
Reference the new `deployment-kubernetes.puml` in the Kubernetes section. The existing Docker Compose diagram moves to the appendix.

**Observability, DLQ, Moderation Rules, Performance Tuning, Troubleshooting:**
These sections are valid for both environments. Remove any Docker Compose-specific assumptions (e.g. `docker exec` commands become `kubectl exec` as the primary example, with Docker Compose equivalent noted where relevant).

**Default Credentials:**
Split into Kubernetes defaults (Helm secrets, Grafana password from secret) and Docker Compose defaults (hardcoded `.env` values). Currently mixed together.

**Appendix A:**
Add a clear banner at the top:
```
NOTE: Docker Compose is the local development and quick-patch environment.
For production deployments, see the Kubernetes Deployment section.
```
