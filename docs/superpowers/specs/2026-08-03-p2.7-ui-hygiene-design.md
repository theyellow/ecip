## 2. Design decisions (approved)

| # | Decision | Choice | Rationale |
|---|----------|--------|-----------|
| D2 | Error handlers | **Per-case: toast user-facing failures, keep background ones quiet** (single `console.warn`, no toast) | Toasting a background poll every few seconds on an outage would spam. |
| D3 | Toast mechanism | Use the **existing `addToast('error', …)` convention** (from `useToast()`), NOT a new helper | Matches established usage (`KnowledgePage`, `IngestionModal`); `emcip-admin-ui/CLAUDE.md` says follow existing patterns. |
| D4 | `key={i}` | **Selective**: replace only where a stable data id exists AND the list can mutate/reorder; leave the genuinely index-correct ones with a comment | Avoids churning correct code; an index key is *right* for an append-only list, a numeric option list, a static prop array, or ephemeral text spans. |

(The original D1 "`npm audit fix --force`" and D5 "toolchain bump is Task 1" are obsolete — RT2-015 shipped in PR #222.)

## 4. U-NEW-1 + U-NEW-3 — per-case error handling

Policy: **user-facing failures toast; background/non-critical failures stay quiet** (one `console.warn`, no toast). Each site's component gains `const { addToast } = useToast()` where it needs to toast.

### Toast (`addToast('error', 'Failed to load … : ' + (e.message || 'Unknown error'))`)
Primary page-data loads and user actions — the user must know it failed:
- `IntegrationsPage.jsx` — the 6 `.catch(console.error)` (global keys `:82`, sources `:194`/`:206`/`:434`, `:262`, own keys `:324`). Message per resource ("Failed to load sources", etc.).
- Tenant-selector loads (an empty selector otherwise fails silently): `KnowledgePage.jsx:89`, `PolicyRules.jsx:198`, `Groups.jsx:167`.
- `Groups.jsx:30` watchers load.
- `PolicyRules.jsx:206`, `Telegram.jsx:64` — **confirm load-vs-action while implementing**; a load the user is waiting on / a user-triggered action → toast.

### Quiet (`console.warn` only, no toast)
Background / non-critical / cleanup — must not spam:
- `Telegram.jsx:49` — per-item status refresh inside a `.forEach`/poll → single `console.warn`.
- `Telegram.jsx:129` — status **poll** (already `console.warn`) — keep as-is.
- `AuthContext.jsx:76` — auth cleanup fire-and-forget.
- `Sidebar.jsx:39` — background prefetch.

Rule for the implementer: if a handler runs inside a **polling loop** or a **fire-and-forget cleanup**, keep it a `console.warn`; otherwise (a load the user is waiting on, or an action they triggered) → `addToast('error', …)`. Do not leave a bare `.catch(() => {})` — every catch either toasts or `console.warn`s with context.

## 5. U-NEW-2 — selective `key={i}` replacement

### Replace — stable id exists + list can change (3 keys, all `Costs.jsx`)
- `Costs.jsx:159` — `byDay.map((d,i)=>…)` chart bars → `key={d.date}` (`d.date` unique per day, confirmed used at `:163`).
- `Costs.jsx:170` — `byDay.map((d,i)=>…)` chart labels → `key={d.date}`.
- `Costs.jsx:202` — `byModel.map((m,i)=>…)` table rows → `key={m.modelName}` (confirmed used at `:203`).

### Leave (index is genuinely correct) — add a `// index key is stable here: …` comment, do NOT churn (6 keys)
- `Flags.jsx:238` — `chatMessages` is **append-only** (`sendChat([...chatMessages, userMsg])`), messages carry no id and the list never reorders → index is correct.
- `DataTable.jsx:31` — `filters` is a static per-page prop array (never reorders/mutates during render).
- `DryRunPanel.jsx:95` — computed dry-run `groupResults`, rendered wholesale, label is literally `Group {i+1}`.
- `PolicyRules.jsx:53` — `<option key={i} value={i}>{i}</option>`: the index **is** the value.
- `PipelineTrace.jsx:122` — ephemeral text-line spans, re-rendered wholesale.
- `ReportViewer.jsx:16` — markdown `<li>` from a content split: ephemeral, re-rendered wholesale.
