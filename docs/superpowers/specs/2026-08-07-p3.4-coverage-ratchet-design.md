# P3.4 — Test coverage gate: per-module ratchet

**Date**: 2026-08-07
**Roadmap item**: P3.4 (`documentation/ROADMAP.md`, tier ① CI net) — ID `#4`
**Status**: design approved, pending implementation plan

---

## Problem

P3.4 was written as "test coverage to 80% — JaCoCo gate". Investigation shows the
gate does not exist for ten of the eleven Java modules.

The JaCoCo plugin is configured in the root `<pluginManagement>` block
(`pom.xml:321-361`) with a `check-coverage` execution enforcing `BUNDLE` / `LINE` ≥
`${jacoco.minimum-coverage}` (0.80). But `<pluginManagement>` only supplies
configuration — it does not activate a plugin. JaCoCo is not a default-lifecycle
plugin, and the only module that declares it in `<build><plugins>` is
`emcip-core/pom.xml:122-125`.

Consequences:

- The agent never attaches for the other ten Java modules, so **no coverage is
  measured** there at all.
- The 80% gate applies to exactly one module.
- The CI step `mvn -B jacoco:report` (`.github/workflows/maven.yml:53`) runs `report`
  standalone with no execution data for those modules, so the uploaded artifact is
  near-empty.

This is the same defect class as P3.1: a plugin configured in `pluginManagement`,
assumed active, never actually running.

Unit tests only (`prepare-agent` + `test` + `report`, forced across all modules),

Two corrections to the roadmap's assumptions:

- The roadmap names intent-classifier, tdlib-adapter and moderation-service as
  weakest. In fact **conversation-context is by far the worst** (25.8%), and
  intent-classifier is the second-*best* Java service.
- **knowledge-engine is the largest block of uncovered code in the repo** (983
  missed lines — more than conversation-context, tdlib-adapter, audit-service and
  moderation-service combined) and the roadmap does not mention it.

`emcip-core` sits at 80.8% against its own 80% gate. A refactor adding roughly six
uncovered lines breaks the build today without anyone having caused a regression.

**These numbers are not the floors.** They are unit-only and pre-`lombok.config`.
Floors are derived from a fresh merged run after sections 1–2 land (see section 3).

## Decisions

| # | Decision | Rationale |
|---|---|---|
| 1 | **Per-module ratchet**, not a global 80% cliff | Makes the gate enforcing immediately instead of blocking the phase on a large test-writing push. 80% becomes the ratchet's destination. |
| 2 | **Merged unit + IT coverage** | P3.1 just activated 15 IT classes. A gate blind to them would push effort toward redundant unit tests for already-IT-covered code. |
| 3 | **Narrow excludes only** | See section 2. Structural excludes of all of `config/` were rejected: they buy +2.3 points while permanently ungating 504 untested lines including SSRF, crypto and tenant-isolation wiring. |
| 4 | **Floor = measured − 2, rounded down** | ~15–50 lines of headroom depending on module size: larger than refactor noise, smaller than a real gap. Avoids the emcip-core failure mode above. |
| 5 | **Scope = infrastructure + worst offenders** | Matches the roadmap's `L` sizing. Driving every module to 80% is `XL` (~1,800 lines) and the final stretch in each module is low-value. |

## Design

### 1. Instrumentation

Move the JaCoCo plugin declaration from `emcip-core/pom.xml` into the **root
`<build><plugins>`** so every module inherits it, and delete the now-redundant
declaration in emcip-core. Configuration stays in `<pluginManagement>`.

Executions, all bound within `verify`:

| Execution | Goal | Output | Property |
|---|---|---|---|
| `prepare-agent` | `prepare-agent` | `target/jacoco.exec` | `surefireArgLine` |
| `prepare-agent-integration` | `prepare-agent-integration` | `target/jacoco-it.exec` | `failsafeArgLine` |
| `merge` | `merge` | `target/jacoco-merged.exec` | — |
| `report` | `report` | `target/site/jacoco` (from merged) | — |
| `check-coverage` | `check` | — (from merged) | — |

**Distinct property names are mandatory.** Both surefire and failsafe read the
`argLine` property by default, so a naive `prepare-agent` +
`prepare-agent-integration` pair collides and the second silently overwrites the
first, losing one set of coverage data. Surefire therefore gets an explicit
`<argLine>${surefireArgLine}</argLine>` and failsafe `<argLine>${failsafeArgLine}</argLine>`.

No `argLine` override exists anywhere in the poms today (verified), so no existing
configuration is disturbed. Both properties are declared empty at root so a
`-DskipTests` build does not fail on an unresolved placeholder.

`gatling-tests` has no `src/main/java` and gets `<jacoco.skip>true</jacoco.skip>`.

### 2. What counts toward coverage

**Lombok.** Add `lombok.config` at repo root:

```
config.stopBubbling = true
lombok.addLombokGeneratedAnnotation = true
```

Lombok then stamps generated members with `@lombok.Generated`, which JaCoCo skips by
default. No such file exists in the repo today, so every generated getter, `equals`,
`hashCode` and `toString` currently counts as uncovered — and the gate correspondingly
rewards assertion-free DTO padding tests. Given Critical Rule #3 (Lombok everywhere),
this is what makes the narrow exclude list sufficient.

**JaCoCo excludes**, limited to:

- `**/dto/**`
- `**/entity/**`
- `**/*Application.class`
- `**/config/*Properties.class` (pure `@ConfigurationProperties` holders)

Everything else stays gated, explicitly including `**/config/**` and `**/security/**`.
Measured impact of the broader exclude that was rejected: 995 lines leave the
denominator at only 40.2% covered, of which `config/` is 791 lines / 504 missed —
including `SsrfConfig`, `CryptoConfig`, `KafkaConfig` and `TenantFilterAspect` (an
aspect enforcing tenant isolation, i.e. behavior rather than wiring).

Counter stays `LINE` on `BUNDLE`, as configured today.

### 3. The ratchet

Each module pom overrides `<jacoco.minimum-coverage>` with its own floor. The root
default drops from `0.80` to `0.00`, so a newly added module inherits a floor it
cannot fail; setting its real floor is then an explicit step in that module's own
PR rather than a surprise build break. The trade-off is accepted deliberately: a
module whose floor someone forgets to set is ungated but visible in
`docs/development/coverage.md`, which lists every module and its floor.

Floors are set from a **fresh merged `mvn -B verify` run performed after sections 1
and 2 land** — the baseline table above is unit-only and pre-Lombok-config, so every
number in it will move. Floor = measured − 2, rounded down to a whole percent.

Governance: raising a floor is a deliberate commit, never automatic. A floor may go
up freely; it may only go **down** with a written reason in the commit body.
`docs/development/coverage.md` records the current floors, the re-measurement
procedure, and this rule.

### 4. Test work — worst offenders

Targeted at code that is effectively untested **and** carries real risk. Not chosen
by percentage.

| Target | Current | Why |
|---|---|---|
| `EnrichmentPipelineService` | 101 missed / 1 covered | Effectively untested pipeline |
| `GraphNodeEmbeddingRepository` | 76 / 1 | Graph-DB writer |
| `KnowledgeEventPublisher` | 36 / 1 | Kafka event publisher |
| `EntityEnrichmentConsumer` | 32 / 2 | Kafka consumer |
| `emcip-conversation-context` (module) | 25.8%, 207 missed | Worst module in the repo |

Written TDD-style where practical, following the existing Testcontainers IT patterns
for the DB-touching cases. Reaching 80% in these modules is not a goal of this item;
closing the dangerous holes is, with raised floors as the side effect.

### 5. CI

`mvn -B verify` already runs `check` once JaCoCo is inherited, so no new workflow
step is required. Changes to `.github/workflows/maven.yml`:

- Remove the now-dead standalone `mvn -B jacoco:report` step (line 53).
- The existing artifact upload (`**/target/site/jacoco`) now finds reports in all
  eleven modules instead of one.

P3.5a made `Java CI with Maven` a required status check, so the coverage gate is
enforced on merge from day one with no further ruleset change.

## Testing strategy

- The instrumentation change is self-verifying: `mvn -B verify` either produces
  merged reports in all modules or fails.
- Verify the argLine collision is actually avoided by confirming both `jacoco.exec`
  and `jacoco-it.exec` exist and are non-empty in a module that has both unit and IT
  tests (e.g. `emcip-admin-api`).
- Verify the Lombok exclusion took effect by confirming a `@Data` class's generated
  accessors no longer appear as missed lines.
- Verify the ratchet bites by temporarily lowering a floor above the measured value
  in a scratch run and confirming the build fails.

## Risks

**The gate goes from advisory-in-one-module to blocking-in-eleven in a single PR.**
If any module's real merged number lands below its floor, `main` blocks.

Mitigation: floors are derived from an actual passing `verify` run inside the PR
itself, so they cannot be wrong at merge time.

**Secondary risk**: `merge` + report over two exec files is more moving parts than
the current setup, and a misconfiguration could silently report *less* coverage
rather than failing loudly. The explicit exec-file check in the testing strategy
covers this.
