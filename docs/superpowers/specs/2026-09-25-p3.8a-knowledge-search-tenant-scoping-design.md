# P3.8a — Knowledge search tenant scoping

**Date:** 2026-09-25 · **Roadmap:** 3.8a (1.0.0 gate) · **Backlog:** TENANT-F1 · **Status:** approved design

## 0. Premise correction

ROADMAP 3.8a describes one method: `GraphNodeEmbeddingRepository.findSimilarNodes(embedding, null, limit)`
reads across tenants. Exploring the search path showed the problem is **systemic and reachable**:

| Query | tenant set | tenant null |
|---|---|---|
| `PgVectorSearchRepository.search` / `hybridSearch` (documents) | own + global | **all tenants** |
| `GraphNodeEmbeddingRepository.findSimilarNodes` | own only | **all tenants** |
| `AgeGraphRepository.findNodesByType` | own only | **all tenants** |
| `GraphNodeEmbeddingRepository.findNearestNeighbour` (entity resolution) | own only | global only |

`tenantId` travels in the `SearchRequest` **body**, and admin-api's `KnowledgeSearchProxyController`
forwards the body verbatim — it ignores the tenant `AdminTenantContextFilter` already resolved from the
JWT. `TENANT_ADMIN`, `MODERATOR` and `ANALYST` all hold `KNOWLEDGE_READ`, so any of them can read another
tenant's knowledge by naming it, or every tenant's by omitting it.

Live data (2026-09-25): all 53 documents and 2,616 graph node embeddings have `tenant_id IS NULL`; there
are no tenant-owned rows. Consequence today: a tenant-scoped **graph** search returns nothing; graph
search only works through the unsafe null branch.

## 1. Decision: the tenant rule

One rule for every knowledge **search** query:

- **tenant set** → that tenant's rows **plus global rows**: `tenant_id = :t OR tenant_id IS NULL`
- **tenant null** → **global rows only**: `tenant_id IS NULL` — never another tenant's rows

"Global" means `tenant_id IS NULL`. This is the rule documents already apply when a tenant is set,
and the null half matches `findNearestNeighbour`. Rejecting null (400) and keeping null = all tenants
were considered and rejected: rejecting breaks today's untenanted callers with no way to ask for global
knowledge; keeping "all" leaves knowledge-engine fail-open for any in-cluster caller.

## 2. Knowledge-engine changes

| Method | Change |
|---|---|
| `PgVectorSearchRepository.search`, `hybridSearch` | null branch: add `AND tenant_id IS NULL`. Tenant branch unchanged. |
| `GraphNodeEmbeddingRepository.findSimilarNodes` | tenant branch: `tenant_id = ? OR tenant_id IS NULL`; null branch: `tenant_id IS NULL`. |
| `AgeGraphRepository.findNodesByType` | same rule in Cypher: tenant → `WHERE n.tenant_id = '<t>' OR n.tenant_id IS NULL`; null → `WHERE n.tenant_id IS NULL`. Tenant stays a formatted UUID (typed `UUID`, not free text). |
| `findNearestNeighbour` | **unchanged** — entity-resolution write logic, not search. |

Javadoc on each method states the rule; `SearchRequest.tenantId` documents that null means global only.
llm-orchestrator's `KnowledgeEngineClient` javadoc ("null = cross-tenant") is corrected to "null = global only".

## 3. admin-api: the proxy binds the tenant

`KnowledgeSearchProxyController.search` and `.getTopics` stop trusting the caller's tenant. The tenant
forwarded to knowledge-engine is resolved from the Reactor context `AdminTenantContextFilter` sets:

| Caller | Forwarded `tenantId` |
|---|---|
| Tenant-bound role (`TENANT_ADMIN`, `MODERATOR`, `ANALYST`, `VIEWER`) | the JWT tenant; any body/query value is **overwritten** |
| `ADMIN` with `X-Tenant-ID` header | the header tenant |
| `ADMIN` without header | the body/query `tenantId` if given (keeps the Knowledge page tenant picker working), else null → global only |

For `search`, the proxy parses the JSON body, sets `tenantId`, and forwards the rewritten body; a body
that is not a JSON object is a 400. For `/graph/topics`, the `tenantId` query parameter is replaced the
same way.

## 4. Testing

Every new assertion is forced to fail once before it counts (project rule — see the verification lesson).

- **knowledge-engine, real Postgres (pgvector + AGE image, existing `IntegrationTest` harness):** seed rows
  for tenant A, tenant B and global. For each of the three queries assert: tenant A → A + global, never B;
  null → global only. Written before the query changes and observed red against today's queries (the tenant-A graph cases fail on missing global rows, every null case fails on tenant-B rows).
- **Existing `GraphNodeEmbeddingRepositoryTest.findSimilarNodes_nullTenant_omitsTenantIdFromBoundArgs`**
  asserts today's leak (`doesNotContain("tenant_id")`); it is rewritten to assert the new rule.
- **admin-api:** a `TENANT_ADMIN` whose body names tenant B has tenant A forwarded; an `ADMIN` body
  choice is forwarded; an `ADMIN` header wins over the body. Verified at the knowledge-engine boundary
  (MockWebServer), not by inspecting the controller.

## 5. Behaviour change

- Tenant-scoped graph search goes from returning nothing to returning the global graph.
- `ADMIN` without a tenant sees global knowledge only instead of all tenants' — no visible difference
  today (no tenant-owned rows exist).
- Tenant-bound users can no longer read other tenants' knowledge.
