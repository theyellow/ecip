# P2.3 — admin-ui Security Response Headers — Design

> **Date**: 2026-07-30
> **Phase**: P2.3 · **Finding**: RT2-007 / RT-029 · **Module**: `emcip-admin-ui`
> **Status**: approved, ready for writing-plans

## Goal

Add HTTP security response headers (CSP, HSTS, X-Frame-Options, X-Content-Type-Options,
Referrer-Policy, Permissions-Policy) to `emcip-admin-ui` via Spring Security, closing RT2-007
(clickjacking, MIME-sniffing, missing transport security, no content-security policy).

## Context (verified against `main`, 2026-07-30)

`emcip-admin-ui` is a Spring Boot **WebMVC** app (servlet stack; `spring-boot-starter-web`),
**not** WebFlux like admin-api. It is a thin BFF:

- `SpaController` serves the Vite-built SPA from `src/main/resources/static`.
- `ApiProxyController` forwards `/api/**` to admin-api.
- It performs **no authentication** — JWT auth lives entirely in admin-api. Spring Security is
  **not** on the classpath today.

Therefore this task is about **response-header hardening**, not authn/authz. The Spring Security
filter chain exists only to write headers; it authorizes every request with `permitAll()`.

Frontend facts that shape the CSP (verified):

- Vite build → hashed JS/CSS assets, **no inline `<script>` code**; no `eval` / `new Function` /
  `dangerouslySetInnerHTML` anywhere in source → strict **`script-src 'self'`** is feasible.
- No CSS-in-JS (no styled-components/emotion/tailwind). Styling is Vite-bundled CSS (`<link>`) plus
  **68 inline `style={{}}` occurrences across 22 files**. React inline styles compile to CSSOM
  mutations governed by CSP `style-src-attr`; a nonce cannot cover them.
- No external browser hosts, no SSE/WebSocket; API is same-origin through the proxy
  (`API_BASE` defaults to `''`) → `connect-src 'self'`, `img-src 'self' data:`, `font-src 'self'`
  are all clean. (`data:` is required by the `data:` SVG favicon in `index.html`.)

## Scope decision — split (agreed 2026-07-30)

The end state is strict `style-src 'self'` with **zero** inline styles. That requires refactoring 68
inline-style occurrences to CSS Modules plus reworking one dynamic chart — a large frontend change.
We **split** that out:

- **This item (P2.3, ships now):** all headers, with CSP `style-src 'self' 'unsafe-inline'`. The
  `'unsafe-inline'` is the single concession the remaining inline styles force. It permits inline
  **style** injection only (a weak vector — no script execution); `script-src` stays strict `'self'`.
- **Follow-up (new backlog item, → P4):** remove all inline styles (→ CSS Modules; `PipelineTrace`
  enum/binary classes; `Costs` bar chart → inline SVG `<rect>` heights), then drop `'unsafe-inline'`
  from `style-src` to reach strict `style-src 'self'`. Sized M. Tracked as **RT2-007-F1** (add to
  `BACKLOG.md` §0b at delivery time).

## Architecture

A single `@Configuration` class, `SecurityConfig`, exposing one `SecurityFilterChain` bean.

```java
@Bean
SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    http.authorizeHttpRequests(a -> a.anyRequest().permitAll())
        .csrf(AbstractHttpConfigurer::disable)     // stateless proxy: no server-side forms/sessions
        .headers(h -> h
            .contentSecurityPolicy(csp -> csp.policyDirectives(CSP_POLICY))
            .httpStrictTransportSecurity(hsts -> hsts
                .includeSubDomains(true)
                .maxAgeInSeconds(31_536_000))       // 1 year, no preload
            .frameOptions(FrameOptionsConfig::deny)
            .contentTypeOptions(Customizer.withDefaults())
            .referrerPolicy(rp -> rp.policy(ReferrerPolicy.NO_REFERRER))
            .permissionsPolicyHeader(pp -> pp.policy(PERMISSIONS_POLICY)));
    return http.build();
}
```

- No `formLogin`/`httpBasic` → no 401 challenge; `permitAll` lets every request through unchanged
  (static assets, SPA routes, `/api/**` proxy, `/actuator/health,info`).
- `csrf().disable()` is required: Spring Security enables CSRF for MVC by default, which would break
  proxied `POST`/`PUT`/`DELETE` requests.

### Exact header values

```
Content-Security-Policy:
  default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
  img-src 'self' data:; font-src 'self'; connect-src 'self';
  frame-ancestors 'none'; base-uri 'self'; form-action 'self'; object-src 'none'
Strict-Transport-Security: max-age=31536000; includeSubDomains
X-Frame-Options: DENY
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Permissions-Policy: geolocation=(), camera=(), microphone=(), payment=()
```

Both `X-Frame-Options: DENY` and CSP `frame-ancestors 'none'` are emitted (legacy + modern
clickjacking coverage).

### Delivery decisions

- **CSP via HTTP response header only — no `<meta>` tag.** The header is authoritative and strictly
  more capable (`frame-ancestors`, `report-to`, `sandbox` are header-only). The finding's meta-tag
  suggestion presupposed static hosting; we control the server, so it is superseded. `index.html`
  is left unchanged.
- **HSTS without `preload`.** `includeSubDomains` is safe (all subdomains are HTTPS behind the
  ingress); `preload` is a hard-to-reverse, domain-wide commitment and is intentionally omitted.
- **Forwarded headers.** TLS terminates at the ingress (RT-032 cert-manager), so admin-ui receives
  HTTP. Set `server.forward-headers-strategy: framework` in `application.yml` so Spring honors
  `X-Forwarded-Proto=https` and Spring Security emits HSTS on the effectively-secure request.

Header string constants (`CSP_POLICY`, `PERMISSIONS_POLICY`) live as `private static final` fields
in `SecurityConfig`.

## Testing

- `SecurityHeadersTest` (`@WebMvcTest(controllers=...)` or `@SpringBootTest` + `MockMvc`, whichever
  wires the security chain): assert each header's **exact** value on
  - a static/SPA route (`GET /`), and
  - a proxied API route pattern (`GET /api/...`, mock the proxy),
  so headers are proven present on both response paths.
- Assert CSP contains `script-src 'self'` **without** `'unsafe-inline'` (guards the strict-script
  invariant against regressions), and that `style-src` contains `'unsafe-inline'` (documents the
  interim state; the follow-up will invert this assertion).
- Manual dev verification: serve the built SPA, confirm **zero** CSP violations in the browser
  console. Optional dev aid: land the policy as `Content-Security-Policy-Report-Only` first to
  surface violations, then switch to the enforcing header before commit.

## Acceptance criteria

1. All six headers above are present with the exact specified values on static and proxied responses.
2. `script-src` is strict `'self'` (no `'unsafe-inline'`, no `'unsafe-eval'`).
3. The SPA loads and functions with **zero** CSP violations in the console.
4. Proxied write requests (`POST`/`PUT`/`DELETE` through `/api/**`) still succeed (CSRF disabled).
5. HSTS is emitted when the request is forwarded as HTTPS (`X-Forwarded-Proto=https`).
6. `spring-boot-starter-security` adds no authentication prompt — every route stays publicly
   reachable exactly as before.
7. Existing admin-ui tests (`AdminUiApplicationTest`) still pass.

## Out of scope

- Removing inline styles / tightening `style-src` to strict `'self'` → **RT2-007-F1** (follow-up).
- Authentication/authorization in admin-ui (remains at admin-api).
- DOMPurify on rendered LLM/Markdown content → **P2.4** (RT2-011/RT2-012).
- Cross-origin isolation headers (COOP/COEP/CORP) — not needed; YAGNI.
