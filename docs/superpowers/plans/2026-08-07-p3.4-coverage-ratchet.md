# P3.4 Coverage Ratchet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the JaCoCo coverage gate actually exist in all eleven Java modules, ratcheted to each module's measured coverage, and close the most dangerous untested code paths.

**Architecture:** JaCoCo moves from `emcip-core`-only into the root `<build><plugins>` so every module inherits it. Unit (surefire) and integration (failsafe) execution data are captured into separate exec files under distinct argLine properties, merged, then reported and checked as one bundle. Each module pins its own floor at `measured − 2` points; the root default becomes `0.00` so a new module cannot inherit a floor it does not meet.

**Tech Stack:** Java 21, Spring Boot 4, Maven, JaCoCo 0.8.12, JUnit 5, Mockito, AssertJ, Testcontainers, Lombok.

**Spec:** `docs/superpowers/specs/2026-08-07-p3.4-coverage-ratchet-design.md`

## Global Constraints

- **Branch:** `feat/p3.4-coverage-ratchet` (already created, branched from `main`). The spec commit `c26cf39` is already on it.
- **Spotless:** run `mvn spotless:apply` before every commit. Success indicator is `0 were changed to be clean`.
- **Liquibase only.** No Flyway. No schema changes are needed in this plan.
- **Lombok:** use `@Slf4j`, `@RequiredArgsConstructor`; never hand-write getters.
- **JaCoCo version:** `0.8.12`, already set as `${jacoco.version}` in root `pom.xml:76`.
- **Floor formula:** `floor = measured − 2 percentage points, rounded down to a whole percent`. Expressed as a decimal, e.g. measured 72.3% → `0.70`.
- **Excludes are exactly:** `**/dto/**`, `**/entity/**`, `**/*Application.class`, `**/config/*Properties.class`. Do not add `**/config/**` or `**/security/**`.
- **Test style:** JUnit 5 + `@ExtendWith(MockitoExtension.class)` + AssertJ `assertThat`, matching `emcip-knowledge-engine/src/test/java/io/emcip/knowledge/engine/service/KnowledgeExtractionServiceTest.java`.
- **Jackson 3:** this project uses `tools.jackson.databind.ObjectMapper`, NOT `com.fasterxml.jackson`. Import accordingly in every test.
- **Docker required** for tasks that run `mvn verify` (Testcontainers-backed ITs).

- [ ] **Step 5: Wire the argLines into surefire and failsafe**

In `<pluginManagement>`, add `<argLine>` to the surefire `<configuration>` (which currently holds only includes/excludes).

**Use `@{...}`, not `${...}`.** Maven interpolates `${...}` in plugin configuration at model-build time, so the empty `<surefireArgLine>` declared in Step 4 is baked in before `prepare-agent` runs and the agent is never attached to the test JVM. Surefire's `@{...}` syntax defers resolution to execution time. The failure is silent: no exec data is written, and JaCoCo's `check` goal *skips* rather than fails when data is missing, so the build goes green reporting zero coverage.

```xml
<configuration>
  <argLine>@{surefireArgLine}</argLine>
  <includes>
    <include>**/*Test.java</include>
  </includes>
  <excludes>
    <exclude>**/*IT.java</exclude>
    <exclude>**/*IntegrationTest.java</exclude>
  </excludes>
</configuration>
```

And to the failsafe `<configuration>`:

```xml
<configuration>
  <argLine>@{failsafeArgLine}</argLine>
  <includes>
    <include>**/*IT.java</include>
    <include>**/*IntegrationTest.java</include>
  </includes>
</configuration>
```

- [ ] **Step 1: Write the measurement script**

Create `scripts/coverage-floors.sh`:

```bash
#!/usr/bin/env bash
# Prints measured line coverage and the ratchet floor (measured - 2, rounded
# down) for every module. Run AFTER a full `mvn -B clean verify`.
set -euo pipefail

printf '%-30s %8s %8s\n' MODULE MEASURED FLOOR
for f in */target/site/jacoco/jacoco.csv; do
  [ -f "$f" ] || continue
  m="${f%%/*}"
  awk -F, -v m="$m" 'NR>1 { miss += $8; cov += $9 }
    END {
      if (miss + cov > 0) {
        pct = 100 * cov / (miss + cov);
        floor = int(pct) - 2;
        if (floor < 0) floor = 0;
        printf "%-30s %7.1f%% %7s\n", m, pct, sprintf("0.%02d", floor);
      }
    }' "$f"
done
```

JaCoCo enforces a **per-module line-coverage floor** during `mvn verify`. The build
fails if a module drops below its floor.

## Floors

| Module | Floor |
|---|---|
| (fill in from `./scripts/coverage-floors.sh`) | |

Root default is `0.00`: a newly added module inherits a floor it cannot fail, so
setting its real floor is an explicit step in that module's own PR.

## Rules

- A floor may be **raised** freely.
- A floor may only be **lowered** with a written reason in the commit body.
- Floors are set at `measured − 2` percentage points, rounded down.

## Re-measuring

```bash

```

Requires Docker — the merged number includes Testcontainers-backed integration tests.

## What counts

Coverage is measured on **merged** unit (surefire) and integration (failsafe)
execution data. Excluded from the denominator: `**/dto/**`, `**/entity/**`,
`**/*Application.class`, `**/config/*Properties.class`. Lombok-generated members are

written, and JaCoCo's `check` goal *skips* rather than fails when data is missing — so
the gate reports success while measuring nothing.

**2. Distinct property names.** Surefire and Failsafe both read the plain `argLine`
property by default. The two `prepare-agent` executions therefore use
`surefireArgLine` and `failsafeArgLine`; giving them the same name silently discards
one set of execution data.

## Notes for the implementer

- **Tasks 1-4 are strictly sequential.** Tasks 5-9 are independent of each other and can be done in any order, but all require Task 1.
- **Docker must be running** for any `mvn verify`. Without it the Testcontainers ITs fail and the merged number is wrong (and floors set from it would be too low).
- **If a test reveals a genuine production bug**, fix it and say so in the commit body — that is the point of the exercise. P3.1 and P3.3 both found live bugs this way (a Testcontainers port-reuse bug and every authorization denial returning 500 instead of 403).
- **Do not chase percentages.** If a class is genuinely trivial, leave it. The floors ratchet from whatever the honest number turns out to be.
