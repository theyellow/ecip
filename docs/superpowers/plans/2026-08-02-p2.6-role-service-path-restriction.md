# P2.6 — ROLE_SERVICE Path Restriction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the `ROLE_SERVICE` BFLA hole (RT2-014) — scope the admin-api service token to `/api/internal/**` (403 elsewhere), model `ROLE_SERVICE` as an empty-permission service identity in the RBAC matrix, and open admin-api's actuator metrics endpoints (fleet-consistent; fixes the broken Prometheus scrape).

**Architecture:** admin-api (WebFlux + R2DBC, reactive). `ServiceTokenAuthenticationFilter` is changed to grant `ROLE_SERVICE` only for `/api/internal/**` and 403 a valid token on any other `/api/**` path; `SecurityConfig.authorizeExchange` permits actuator metrics + reserves `/api/internal/**` for `ROLE_SERVICE`; `RolePermissions` documents the identity without adding it to the user `Role` enum.

**Tech Stack:** Java 21, Spring Boot 4, Spring WebFlux Security (reactive), Maven, JUnit 5, AssertJ, Reactor `StepVerifier`, `MockServerWebExchange`.

- [ ] **Step 3: Implement the filter**

Replace the `filter(...)` method body in `ServiceTokenAuthenticationFilter.java` and add the constant. New content of the method + constant:
```java
    private static final String INTERNAL_PATH_PREFIX = "/api/internal/";

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, WebFilterChain chain) {
        String path = exchange.getRequest().getPath().value();

        // Non-/api/ paths (e.g. /actuator/**) are not service-token gated — matches the fleet pattern
        // and keeps Prometheus scraping working.
        if (!path.startsWith("/api/")) {
            return chain.filter(exchange);
        }

        String serviceToken = exchange.getRequest().getHeaders().getFirst(SERVICE_TOKEN_HEADER);
        if (serviceToken == null) {
            // No service token — let the JWT filter authenticate the user request.
            return chain.filter(exchange);
        }

        if (!MessageDigest.isEqual(
                configuredServiceToken.getBytes(StandardCharsets.UTF_8),
                serviceToken.getBytes(StandardCharsets.UTF_8))) {
            log.warn("Invalid X-Service-Token from {}", exchange.getRequest().getRemoteAddress());
            exchange.getResponse().setStatusCode(HttpStatus.UNAUTHORIZED);
            return exchange.getResponse().setComplete();
        }

        // Valid service token: authorize ONLY internal service-to-service paths (RT2-014).
        if (path.startsWith(INTERNAL_PATH_PREFIX)) {
            UsernamePasswordAuthenticationToken auth =
                    new UsernamePasswordAuthenticationToken(
                            "service", null, List.of(new SimpleGrantedAuthority("ROLE_SERVICE")));
            return chain.filter(exchange)
                    .contextWrite(ReactiveSecurityContextHolder.withAuthentication(auth));
        }

        // Valid token on a non-internal path — the service token is not permitted here (BFLA fix).
        log.warn(
                "Service token presented on non-internal path {} from {}",
                path,
                exchange.getRequest().getRemoteAddress());
        exchange.getResponse().setStatusCode(HttpStatus.FORBIDDEN);
        return exchange.getResponse().setComplete();
    }
```
(Keep the existing imports, `SERVICE_TOKEN_HEADER`, `DEFAULT_TOKEN`, `@Value configuredServiceToken`, and `@PostConstruct validateToken()` unchanged.)

## Notes for the implementer

- **The security-critical change is the filter (Task 1).** The `authorizeExchange` rules (Task 2) are declarative defense-in-depth; `/api/internal/**` has no endpoints yet (reserved), and the actuator permits fix a real scrape gap. There is no assembled-chain integration-test harness in this repo (P1-M1); do not build one here — the filter unit tests carry the enforcement proof.
- **403 vs 401:** a *valid* token on a non-internal `/api/**` path returns **403** (authenticated-but-forbidden); an *invalid* token on `/api/**` returns **401**; absent token passes through to the JWT filter. Keep these distinct.
- **Do not add `SERVICE` to the `Role` enum** — it would become user-assignable (JWT `role` claim, `UserManagementService`). Model it only as `SERVICE_PERMISSIONS` in `RolePermissions`.
- **After Task 3:** hand off to `superpowers:finishing-a-development-branch`; backfill the real PR number into the BACKLOG `#NNN` at PR creation.
