- **Toast convention** — do NOT invent a helper; match existing `KnowledgePage`/`IngestionModal` usage: `import { useToast } from '<correct relative path>/components/Toast/useToast'`, then `const { addToast } = useToast()`, then `addToast('error', \`Failed to … : ${e.message || 'Unknown error'}\`)`. Read a current caller (e.g. `KnowledgePage.jsx`) to copy the exact import path and call signature — the `addToast(type, message)` API.
- **Error-handler rule:** a handler in a **polling loop** or **fire-and-forget cleanup** → single `console.warn('<context>:', e?.message || e)` (no toast); a **load the user waits on** or a **user-triggered action** → `addToast('error', …)`. Never leave a bare `.catch(() => {})`.
- **`key={i}` rule:** replace only where a **stable id exists AND the list can change**; where index is genuinely correct, LEAVE it with a `// index key is stable here: …` comment. Do not churn correct keys.
- Never weaken/skip/delete a test to make the suite pass. All ~26 suites / 144 tests stay green; test output stays pristine (the one pre-existing jsdom "Not implemented: navigation" line in `ReportViewer.test.jsx` is unrelated and predates this work).

## Notes for the implementer

- **Toast vs quiet is the judgment in Task 1** — when unsure whether a catch is background or user-facing, ask: is a user waiting on this result, or did they trigger this action? If yes → toast. If it's a poll/refresh/cleanup running on its own → `console.warn`. The spec §4 table is the default; confirm each site's context while editing.
- **Do not over-churn keys (Task 2)** — only the 3 Costs keys get replaced; the other 6 get a one-line comment, not a rewrite. The point is stable identity for *changeable* lists, not eliminating every `key={i}`.
