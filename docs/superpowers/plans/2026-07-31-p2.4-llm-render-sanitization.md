# P2.4 — LLM/Markdown Render Sanitization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `sanitizeText()` layer to the two admin-ui LLM/Markdown render paths (RT2-011 `ReportViewer`, RT2-012 `Flags` chat) so hostile Unicode (bidi/zero-width/control) is stripped and any future HTML sink is pre-covered by DOMPurify.

**Architecture:** A single pure util `src/utils/sanitizeText.js` runs DOMPurify in strip-tags-to-plain-text mode (`RETURN_DOM` + `textContent`, which avoids double-encoding when the result is handed to a React text node) followed by three Unicode-hygiene regex passes. It is applied at all four content paths: ReportViewer render + `.md` download, Flags chat render + Copy button.

**Tech Stack:** React 18 SPA, Vite, Vitest + jsdom (`environment: 'jsdom'`, `globals: true`, so `test`/`expect`/`vi` and `document` are available without imports), `@testing-library/react`, new runtime dependency `dompurify`.

```js
})

test('removes C0/C1 control chars but preserves tab and newline', () => {
  expect(sanitizeText('a\u0000b')).toBe('ab')
  expect(sanitizeText('line1\nline2\tend')).toBe('line1\nline2\tend')

  expect(sanitizeText(md)).toBe(md)

  expect(sanitizeText(null)).toBe('')
  expect(sanitizeText(undefined)).toBe('')
  expect(sanitizeText(42)).toBe('')
  expect(sanitizeText({})).toBe('')
})
```

Note on the first two expectations: `KEEP_CONTENT: true` keeps the *text* inside
most stripped tags, but DOMPurify's default `FORBID_CONTENTS` set (which includes
`script` and `style`) discards their inner text entirely — so
`<script>alert(1)</script>Hello` yields `Hello`, and a self-closing `<img>` (no
text content) yields `''`. Ordinary tags like `<b>hi</b>` would keep `hi`.

- [ ] **Step 4: Write the implementation**

Create `src/utils/sanitizeText.js`:
```js
import DOMPurify from 'dompurify'

// C0 (minus \t \n \r) + C1 control chars.
// eslint-disable-next-line no-control-regex
const CONTROL = /[\u0000-\u0008\u000B\u000C\u000E-\u001F\u007F-\u009F]/g
// Zero-width space/non-joiner/joiner, word-joiner, BOM.
const ZERO_WIDTH = /[\u200B-\u200D\u2060\uFEFF]/g
// Bidi embeddings/overrides + isolates (Trojan-Source).
const BIDI = /[\u202A-\u202E\u2066-\u2069]/g

/**
 * Sanitize LLM-generated text for display, download, or clipboard.
 *
 * There is no HTML sink in this app (content is rendered via React text nodes),
 * so the DOMPurify pass is defense-in-depth forward-cover for any future HTML
 * sink. The active mitigation is the Unicode hygiene pass, which removes
 * bidi/zero-width/control characters that React escaping does NOT neutralize.
 *
 * DOMPurify is invoked with RETURN_DOM + textContent (not the default string
 * return) so its HTML-encoded output is not double-escaped by React.
 */
export function sanitizeText(raw) {
  if (typeof raw !== 'string') return ''
  const stripped =
    DOMPurify.sanitize(raw, {
      ALLOWED_TAGS: [],
      ALLOWED_ATTR: [],
      KEEP_CONTENT: true,
      RETURN_DOM: true,
    }).textContent ?? ''
  return stripped.replace(CONTROL, '').replace(ZERO_WIDTH, '').replace(BIDI, '')
}
```

## Notes for the implementer

- **Why not the default `DOMPurify.sanitize()` return value:** it HTML-encodes for `innerHTML` insertion; our sinks are React text nodes, which escape again → visible `&amp;`/`&gt;` corruption in every report. `RETURN_DOM` + `.textContent` yields decoded plain text, so React escapes exactly once. This is the single most important detail — the double-encode regression tests in Tasks 1–3 exist to lock it.
- **jsdom + DOMPurify:** the test env is `jsdom` with `globals: true` (`vite.config.js`), so `document`/`window` exist and DOMPurify auto-binds on import; no per-file `@vitest-environment` annotation is needed.
- **Node 24 Blob:** `blob.text()` (Task 2 download test) is available on the global `Blob`; jsdom provides `URL` but the test stubs `createObjectURL`/`revokeObjectURL` because jsdom does not implement object URLs.
- **Scope:** logic-only. No CSS/token changes, no markdown-feature expansion (rich markdown is explicitly out of scope per spec §7).
